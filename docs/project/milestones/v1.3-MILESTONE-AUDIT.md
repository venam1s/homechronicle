## Tech Debt / Open Items

### A. Post-milestone bugs surfaced (CRITICAL FOR DECISION)

User reported "everything stale after a few days" on 2026-04-27. Diagnosis showed two bugs in the device-health/repair interaction that v1.3 did NOT address:

1. **`lastHealthyAt` heartbeat missing** (fixed in quick task `260427-ttq`, 3 commits, 9 new tests):
   - `device-health.js` rescue clause depended on `subscriberConnectedAt` which is set ONCE at TCP connect and never refreshed for healthy long-lived connections → rescue expired ~15 min after connect.
   - `getRepairTargets()` keyed `isStale` off `lastSubscribedAt > 10min` (also one-shot) → daily repair cycle needlessly tore down every healthy connection.
   - Fix: added `stats.lastHealthyAt`, refreshed on each HAP event + on subscribe success; threaded into `deriveDeviceHealth` rescue + `getRepairTargets` staleness check.

2. **Quiet-device gap** (fixed in quick task `260427-vch`, 2 commits, 8 new tests):
   - Even with `lastHealthyAt`, a connected-but-silent device (quiet sensor, unused switch) still flipped to stale after 15min because no events flowed to refresh the timestamp.
   - Fix: `getSubscriberStats()` now exposes `connected: Boolean(session?.client)`; `deriveDeviceHealth` short-circuits rescue to 'online' whenever `subscriberConnected === true`, regardless of timestamp age.

**Combined effect:** Active devices, quiet devices, and matter accessories all behave correctly; the daily repair scheduler only acts on genuinely broken connections.

**Test count:** 320 (start of v1.3 audit) → 337 (after both quick tasks).
