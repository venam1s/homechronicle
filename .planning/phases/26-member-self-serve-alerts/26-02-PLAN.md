Validation functions:
- validateCreate(body) / validatePatch(body) are pure (no session). Do the member-email override in the HANDLER after validate (override value.targetEmail), not inside these pure functions — keeps them testable.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser/session → alerts-router | Authenticated user-supplied rule bodies (name, channel, target_url, target_email, user-controllable :id) cross here |
| service-token caller → alerts-router | API_TOKEN-only callers (no session) attempt owner-requiring writes |
| alerts-router → outbound webhook | rule target_url drives an outbound request (SSRF surface, now all authed users) |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-26-IDOR | Elevation/Tampering | PATCH/DELETE /rules/:id | mitigate | `WHERE id=$id AND user_id=$uid` → 0 rows → 404 (D-07); Task-1 IDOR test asserts B's row unchanged when A targets it |
| T-26-OWNER-FORGERY | Spoofing | POST /rules body | mitigate | user_id sourced from req.hcSession.user_id only; req.body.user_id ignored (D-07) |
